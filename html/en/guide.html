Quick mnemonics

One acronym per module. Remember the acronym and you recover the four pillars.

📌 Module 1 — T.C.M.S · MSO Foundations

  • T · Tokens — the unit of everything: prompt, history, tool schemas, results and response. The tokenizer depends on the model.
  • C · Context — a fixed budget. Oversized input = validation error; ceiling hit during generation = partial output with model_context_window_exceeded.
  • M · Sampling — every token is sampled from a distribution, hence the non-determinism. New models reject temperature/top_p/top_k with a 400.
  • S · Selection — model and thinking mode are two independent controls that compose.

📌 Module 2 — P.E.S.A · Production-grade prompting

  • P · System prompt — the persistent contract that applies to every response.
  • E · XML tags — they separate instructions from data.
  • S · Samples (few-shot) — they show the pattern instead of describing it.
  • A · Applying output constraints — format constraints; their evolution is output_config.format: json_schema.

📌 Module 3 — P.C.S.A · Claude Code, MCP and integration

  • P · Permissions — default, acceptEdits, plan, auto, allowlist, bypass. A deny rule always wins.
  • C · Configuration — CLAUDE.md is prepended to the context on every session; rules files scope by path; hooks enforce deterministically.
  • S · Skills and plugins — reusable workflows; the plugin bundles them with hooks, subagents and MCP.
  • A · Authentication — secrets in environment variables or a secrets manager, never in the repository.

📌 Module 4 — E.R.C.S · Production, evals and security

  • E · Evals — they turn "done" into a number. Coverage > rubric perfection.
  • R · Resilience and tracing — four testing levels + traces that localize the step that failed.
  • C · Cost — levers: model, context size, number of tool calls, caching and batching.
  • S · Security — the reliable boundary is the action one, not the wording of the prompt.

📌 Module 5 — E.P.R.L · Accelerators and IP contribution

  • E · Encapsulation — the next engagement configures the asset instead of rebuilding it.
  • P · Preparation to contribute — focused code, runnable example, test, assumptions and confirmed rights.
  • R · Requirements — functional (what it does) and infrastructure (where and under what constraints it runs).
  • L · Lifecycle — development → evaluation → staging → production, with a pinned model id.

⚠️ The 10 most expensive mistakes

  1. Asserting exact text in tests → assert properties (structure, range, field present).
  2. Rewording the prompt without diagnosing → identify the failure type before rewriting.
  3. Turning on extended thinking for classification → wasted tokens; it pays off on multi-step problems.
  4. Putting a secret in CLAUDE.md or .mcp.json → read it from the environment and back the rule with a PreToolUse hook.
  5. Omitting the tool_result after a tool_use → the API rejects the next request.
  6. Connecting MCP servers without filtering → every connected server fattens every request.
  7. Not documenting requirements before coding → scope creep and rework.
  8. Using a model alias in production → an upstream update becomes a silent change.
  9. Forgetting the human gate before an irreversible action → damage that is hard to undo.
  10. Not treating fetched content as data → successful prompt injection.

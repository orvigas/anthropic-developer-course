Mnemotecnia rápida

Una sigla por módulo. Si recuerdas la sigla, recuperas los cuatro pilares.

📌 Módulo 1 — T.C.M.S · Fundamentos MSO

  • T · Tokens — unidad de todo: prompt, historial, esquemas de herramientas, resultados y respuesta. El tokenizador depende del modelo.
  • C · Contexto — presupuesto fijo. Entrada sobredimensionada = error de validación; techo alcanzado durante la generación = salida parcial con model_context_window_exceeded.
  • M · Muestreo — cada token se muestrea de una distribución, de ahí el no-determinismo. Los modelos nuevos rechazan temperature/top_p/top_k con error 400.
  • S · Selección — modelo y modo de razonamiento son dos controles independientes que se componen.

📌 Módulo 2 — P.E.S.A · Prompting de grado de producción

  • P · Prompt de sistema — contrato persistente que aplica a cada respuesta.
  • E · Etiquetas XML — separan instrucciones de datos.
  • S · Samples (few-shot) — muestran el patrón en lugar de describirlo.
  • A · Acotar la salida — restricciones de formato; su evolución es output_config.format: json_schema.

📌 Módulo 3 — P.C.S.A · Claude Code, MCP e integración

  • P · Permisos — predeterminado, acceptEdits, plan, auto, allowlist, bypass. Una regla deny siempre gana.
  • C · Configuración — CLAUDE.md se antepone al contexto en cada sesión; archivos de reglas acotan por ruta; los ganchos aplican de forma determinista.
  • S · Skills y plugins — flujos reutilizables; el plugin los empaqueta con ganchos, subagentes y MCP.
  • A · Autenticación — secretos en variables de entorno o gestor de secretos, nunca en el repositorio.

📌 Módulo 4 — E.R.C.S · Producción, evaluaciones y seguridad

  • E · Evaluaciones — convierten "listo" en un número. Cobertura > perfección de rúbrica.
  • R · Resiliencia y rastreo — cuatro niveles de prueba + trazas que localizan el paso que falló.
  • C · Costo — palancas: modelo, tamaño de contexto, número de llamadas a herramientas, caché y lotes.
  • S · Seguridad — el límite fiable es el de la acción, no la redacción del prompt.

📌 Módulo 5 — E.P.R.L · Aceleradores y contribución IP

  • E · Empaquetamiento — el siguiente compromiso configura el activo en lugar de reconstruirlo.
  • P · Preparación para contribuir — código enfocado, ejemplo ejecutable, prueba, supuestos y derechos confirmados.
  • R · Requisitos — funcionales (qué hace) e infraestructura (dónde y bajo qué restricciones corre).
  • L · Lifecycle — desarrollo → evaluación → staging → producción, con ID de modelo fijado.

⚠️ Los 10 errores más costosos

  1. Afirmar texto exacto en las pruebas → afirma propiedades (estructura, rango, campo presente).
  2. Reformular el prompt sin diagnosticar → identifica el tipo de fallo antes de reescribir.
  3. Activar pensamiento extendido en clasificación → desperdicio de tokens; sirve en problemas de varios pasos.
  4. Poner un secreto en CLAUDE.md o en .mcp.json → léelo de entorno y respalda la regla con un gancho PreToolUse.
  5. Omitir el tool_result tras un tool_use → la API rechaza la siguiente solicitud.
  6. Conectar servidores MCP sin filtrar → cada servidor conectado engorda cada solicitud.
  7. No documentar requisitos antes de codificar → scope creep y trabajo rehecho.
  8. Usar un alias de modelo en producción → una actualización aguas arriba se vuelve un cambio silencioso.
  9. Olvidar la puerta humana antes de una acción irreversible → daño difícil de deshacer.
  10. No tratar el contenido descargado como datos → inyección de prompts exitosa.
